# Политика безопасности

VaultAccess — локальное приложение. У него нет сервера, аналитики и сетевых запросов, поэтому основная модель угроз связана с устройством, браузером и резервными копиями.

## Поддерживаемые версии

Актуальная ветка — **2.x**. Исправления безопасности выходят для последней версии.

## Как сообщить об уязвимости

Не создавайте публичный issue с эксплойтом. Используйте **GitHub Security Advisory → Report a vulnerability** в репозитории проекта. Если репозиторий ещё не опубликован, свяжитесь с владельцем приватно.

В сообщении укажите:

- версию и способ запуска (`build:single`, dev-сервер, браузер);
- шаги воспроизведения;
- возможное влияние;
- PoC, если он безопасен.

## Криптографическая модель

- **Мастер-пароль** не сохраняется ни в IndexedDB, ни в файлах.
- **PBKDF2-HMAC-SHA-256**, 600 000 итераций, случайная соль 16 байт — выводит неизвлекаемый ключ.
- **AES-256-GCM** шифрует весь JSON-документ хранилища (пароли, заметки, TOTP, настройки).
- **IV** — 12 случайных байт на каждое сохранение.
- Ключ создаётся с `extractable: false`; живёт только в памяти вкладки.
- При блокировке ссылки на ключ и расшифрованные данные очищаются; React-состояние размонтируется.
- Целостность проверяется аутентификационным тегом GCM: неверный пароль или изменённый шифротекст не расшифруются.

Формат шифрованного бэкапа: `{ format: "vaultaccess-v2", salt, iterations, iv, cipher, updatedAt }`.

## Что защищено

- Данные **at rest** в IndexedDB: без мастер-пароля их не прочитать.
- Резервные копии в файлах: тот же шифрованный конверт.
- TOTP-секреты: хранятся внутри зашифрованного блока.
- Копирование: буфер обмена очищается через заданный интервал (по умолчанию 30 секунд), если браузер/ОС это позволяют.
- Markdown-превью: HTML санитизируется DOMPurify; ссылки открываются с `noopener noreferrer`.
- Поиск: пароли намеренно не индексируются.
- Сеть: приложение не содержит запросов к API, CDN, шрифтам и аналитике.

## Что не защищено

Локальное приложение не может защитить от:

- вредоносного ПО, кейлоггера или руткита на устройстве;
- вредоносного браузерного расширения с доступом к странице/IndexedDB;
- скомпрометированного браузера или ОС;
- физического доступа, если устройство разблокировано и хранилище открыто;
- скриншотов и записи экрана;
- слабого мастер-пароля и его повторного использования;
- потери устройства без резервной копии;
- XSS в сторонней зависимости (снижается lockfile, CI и санитизацией, но не исключается полностью);
- атак на цепочку поставок npm.

## Резервные копии

- Мастер-пароль **невосстановим**. Потеря пароля означает потерю данных.
- Делайте как минимум одну копию вне устройства (внешний диск, менеджер паролей, защищённое хранилище).
- Старые бэкапы открываются **старым** мастер-паролем после его смены.
- Открытый JSON/CSV/Markdown не шифруется. Храните такие файлы только временно и удаляйте.
- Автобэкап в файл использует File System Access API и разрешение браузера. Проверяйте, что файл действительно обновляется.

## Хранение и удаление

- Новая база: IndexedDB `vaultaccess_v2`, хранилища `vault` и `meta`.
- Старая база: `vaultaccess_db` — не изменяется новым приложением.
- «Удалить хранилище» стирает `vaultaccess_v2` и отключает автобэкап. Файлы бэкапов остаются.
- Очистка данных сайта в браузере также удаляет хранилище. Сначала сделайте экспорт.

## Зависимости

- Зависимости зафиксированы в `package-lock.json`.
- CI выполняет typecheck, тесты и обе сборки.
- Dependabot настроен на еженедельные обновления npm и GitHub Actions.
- Перед обновлением зависимостей проверяйте changelog и diff.

## Рекомендации пользователю

1. Используйте длинный уникальный мастер-пароль (12+ символов).
2. Включите автобэкап или регулярно делайте шифрованный экспорт.
3. Не открывайте приложение на чужом устройстве и не оставляйте вкладку разблокированной.
4. Установите минимальную автоблокировку, которая удобна.
5. Проверяйте слабые/старые/повторяющиеся пароли на экране «Обзор».
6. Не пересылайте открытые экспорты в мессенджерах.
7. Держите браузер и ОС обновлёнными.
